# 短视频审校

用于审校短视频脚本/口播文案。目标不是把稿子重写得更漂亮，而是判断它能不能成立、哪里会掉播放、哪里可能违规，以及下一步应该怎么改。

## 核心边界

- **只诊断，不输出修订全文**：可以给改进方向、局部示例和优先级，不直接生成完整新版文案。
- **问题要可定位**：每条关键问题必须给出原文片段、问题归因、参考规则，找不到条款支撑的诊断无效。
- **短视频优先**：允许口播里的轻微信息拥挤、悬念留白、反常识缺口；不要按长文标准误判。
- **默认会配画面**：证据、截图、界面细节可由画面承担；只有文案无法理解或无法复述时才判为缺失。

## 审校流程

### 0. 推理初始化（后台执行，不在报告中展示细节）

启动审校前：

1. 优先扫描 `output/` 目录，找到与当前输入文本「场景/痛点」最接近的 **2 个**历史案例。
2. 深度分析案例中的推理过程：
  - 若匹配案例标签为 `[差款]`：重点学习"哪里做得差/踩了哪些坑"，用于本次**找茬与规避**。
  - 若匹配案例标签为 `[爆款]`：重点学习"哪些结构与钩子有效/如何制造压强"，用于本次**上限抬升**。
  - 禁止生搬硬套词汇，模仿其「权衡利弊、洞察人性、极限压强」的思维方式。

### 1. 输入整理

判断用户给的是完整稿、开头片段、选题描述，还是历史案例复盘。若是完整稿，给文本加行号；若是片段，明确只能审片段，不假装审完整链路。

### 2. 业务类型判断

判断是否属于 AI 业务，若是则全程对照 `references/business-variables.md`：

- AI 游戏/模拟实验：重点看恶意规则、持续施压、规则是否 50 字内可懂。
- AI 生活/职场：重点看真实代价、群体代入、打工人/平台/规则冲突。
- AI 科普/技术：重点看是否能降维成大众可懂的事件。
- 非 AI 业务：跳过业务变量，用通用选题、结构、行文、合规审校。

### 3. 生存性过滤

先查会让稿子直接不成立的硬伤：

- 合规红线：色情低俗、未成年人风险、违法暴力、医疗夸大、敏感主体、负面品牌露出。
- 选题不及格：无爆点、受众过窄、主体模糊、没有事件承载、情绪基调不清。
- AI 业务硬伤：只讲单人小事、没有实质代价、AI 没有拟人化行为、整活类把网友写成负面找骂对象。

若命中硬伤，先输出硬伤结论和最小改法，**不继续堆细碎行文问题**。

### 4. 结构与事件链审校

把稿子分为 **开头 / 事件 / 结尾**：

- 开头：前 50 字是否有冲突、反常识、强悬念，且承诺与正文一致。
- 事件：是否有 3 次递进事件 + 1 个干净落脚点；每轮形式变化、结果明确、情绪升级。
- 结尾：可以是绝境、讽刺、反问，也可以是情绪高潮释放；避免成功学说教、冗长升华、情绪悬空收不住。

优先抓「事儿够不够大」「因果能否复述」「递进是否成立」「钩子是否兑现」。

### 5. 读者 Context 与行文审校

结合目标受众判断，不要脱离受众谈信息差：

- 目标受众已熟悉的词，不标为背景缺失。
- 真正陌生的专有名词、断裂因果、抽象心理、无画面动作，要标出。
- 短视频允许一句承载 2 个紧密信息；只有长难句、结构套娃、读完找不到主干时才要求拆句。
- 客观解说靠事实排列制造情绪，不靠粗暴骂人和空泛形容词。

### 6. 多模态建议

只给能提升理解或留存的画面建议：

- 开头 5 秒画面是否一眼看懂主体。
- 策略/实验类是否保持统一画面，不频繁切走。
- 关键数据、规则升级、反转节点是否有高亮、字幕或 UI 提示。
- 是否存在密集文字、脏乱画面、难辨字体、强不适画面。

## 输出格式

### 诊断四件套（每条问题必须包含）

**【行号/片段】 + 【问题归因】 + 【规则编号】 + 【改进方向】**

其中【规则编号】必须是可回溯的 `references/` 原子条款，写法：`[文件 -> 条目]`。

### 报告结构

```
## 审校结论
选题结论：[通过/不通过/需重做]
标签判断：[爆款潜力/普通/差款风险]
优先级：[先改选题/先改结构/先改行文/先处理合规]

## 关键问题
1. 【行号/片段】...
   - 问题归因：...
   - 依据：[references/... -> 条目]
   - 影响：...
   - 改进方向：...

## 可保留的优点
- ...

## 下一步建议
- ...
```

### 落盘规范（用户要求写入时执行）

- 原文带行号写入 `drafts/`。
- 完整诊断过程写入 `drafts/YYYYMMDD-关键词-诊断过程.md`，**不写入** `output/`。
- 推理版报告写入 `output/案例-关键词-推理版.md`，必须包含：
  - **标签**：`标签：[爆款]/[差款]`（写在文件顶部）
  - **[场景描述]**
  - **[原始输入]**（带行号）
  - **[核心推理]**：业务类型判断 → 参考历史案例 → 逻辑迁移 → 审校流程思考
  - **[最终输出]**：选题结论 + 标签结论开头，然后是四件套摘要 + 能显著提升上限的改进方向

未产出推理版视为未完成；把诊断报告写进 `output/` 而漏推理版，视为错误。

## 5 大改进标尺

对照以下标准评估文案上限，仅当建议能显著提升上限时才纳入输出：

- **受众广**：能破圈层，且不削弱冲突双方的对立性。
- **矛盾强**：靠事件编排（攻防/代价/递进）产生张力。
- **钩子狠**：前 50 字必须有冲突或反常识。
- **节奏快**：事件链紧凑，剔除所有"情绪水话"。
- **结尾干净**：以事件绝境或讽刺/反问收束，不给缓冲，瞬间黑屏。

## 质量自检

输出前检查：

- 是否误把钩子留白当成逻辑缺失？
- 是否误把画面可承担的信息当成文案缺失？
- 是否给了原文片段和依据，而不是泛泛评价？
- 是否避免输出完整重写稿？
- 是否优先处理硬伤，而不是堆细枝末节？
- 是否误把口语化的事件快速跳跃当成书面因果缺失？（口播逻辑听觉成立即可，不要求每步有明确桥接词）
