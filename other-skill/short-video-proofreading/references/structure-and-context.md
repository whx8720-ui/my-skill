# 结构诊断与读者 Context

用于检查短视频脚本的事件结构、开头承诺、结尾收束和读者理解成本。

## 1. 三项原则

- **最小改动原则**：能保留原稿就保留；需要调整时说明改动原因。
- **重点突出原则**：事件围绕一个核心立意展开，不分散、不堆砌。
- **核心点一致原则**：钩子、正文展开、结尾落点必须同向，避免「开头讲 A、正文讲 B」。

## 2. 开头、事件、结尾

审校时先标出三部分：

| 部分 | 标准 | 常见问题 |
| --- | --- | --- |
| 开头 | 前 50 字有冲突、反常识或强悬念 | 背景铺垫过长；钩子无冲突；钩子承诺与正文错位 |
| 事件 | 冷静客观叙述，事件递进，让人越听越生气/越听越想看 | 平铺直叙；多件事性质相同；结果不明确；因果不可复述 |
| 结尾 | 有重力感收束：事件绝境、讽刺或反问 | 成功学说教；冗长升华；提前总结后又继续讲 |

## 3. 事件链标准

推荐结构：**3 次递进事件 + 1 个落脚点**。

- 一轮：建立规则、冲突或代价。
- 二轮：规则升级、对抗升级或结果反转。
- 三轮：出现更离谱的后果、补刀或更高代价。
- 落脚点：主体被逼入死胡同，或用讽刺/反问留下余味。

每轮都要检查：

- 形式是否变化。
- 每轮是否有清晰结果。
- 情绪是否递进。
- 观众是否能用「先怎样、然后怎样、最后怎样」复述。

## 4. 常用事件链类型

| 类型 | 说明 | 适用 |
| --- | --- | --- |
| 连锁反应 | A 触发 B，B 触发 C，前事驱动后事 | 人 vs 规则、平台测试、荒诞破防 |
| 幸存者偏差逆向重构 | 从结果倒推被隐藏的筛选条件或失败者 | 揭穿表象、反转认知 |
| 随机性的恶意奖励 | 运气/随机性被误当能力，错误反被奖励 | 荒诞、不公、毒鸡汤 |
| 道德绑架的极限悖论 | 正确选择被推到极端后变成两难 | 站队、人性两难、嘴替 |
| 特洛伊木马式信息差 | 表面一事，关键信息藏在暗处 | 你以为 X，其实 Y；生活信息差 |

## 5. 易误判项

| 情形 | 不要误判为 | 正确理解 |
| --- | --- | --- |
| 反常识缺口 | 逻辑跳跃 | 若服务于钩子，允许先留白，后文再揭晓 |
| 悬念式开头 | 信息缺失 | 悬念能驱动继续观看时，不算缺陷 |
| 文案未写截图/证据 | 缺证据 | 画面可承担截图、界面、细节，文案不必重复 |
| 轻微信息拥挤 | 长难句 | 短视频允许一句承载 2 个紧密信息 |

## 6. 读者 Context 检查

核心问题：目标受众看这里会不会不明所以？

先确认受众，再判断是否需要解释：

- AI 业务：18-35 岁、对科技/AI、打工人、平台规则、硅谷叙事较敏感。
- 游戏业务：默认游戏圈层受众，常见游戏机制和黑话不必都解释。
- 泛社会新闻：默认五年级阅读水平、初中左右受教育程度。

| 检查项 | 问题表现 | 改进方式 |
| --- | --- | --- |
| 背景假设 | 当前受众仍陌生的专有名词、缩写、梗未解释 | 补一句解释，或改成更大众的说法 |
| 自说自话 | 「就是那种...」但没说清是哪种 | 具体化描述 |
| 跳跃逻辑 | 从 A 到 C，缺少必要 B | 补过渡；若是钩子留白则不判问题 |
| 隐含情绪 | 「实在是太...」但没有铺垫 | 先给事实，再给情绪 |
| 信息差 | 假设读者知道来龙去脉 | 简要交代背景 |
| 画面感缺失 | 抽象概括多，缺动作、场景、感官细节 | 补「谁在哪做了什么」 |
| 中途收束词 | 中间出现「最后」「总之」「说到底」 | 改成递进词，把收束留给结尾 |

## 7. 结构输出要求

输出结构问题时给：

- 开头/事件/结尾的位置。
- 问题片段。
- 归因：钩子、递进、因果、结尾、读者 Context 等。
- 最小修改方向。

示例依据写法：`依据：structure-and-context.md -> 事件链标准 -> 3 次递进事件 + 1 个落脚点`。
