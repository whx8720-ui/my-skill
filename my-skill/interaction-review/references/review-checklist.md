# 交互评审检查清单

> 评审时按 P0 → P1 → P2 顺序逐项检查，P0 未通过不进入 P1 细节讨论。

## P0：整体交互链路（核心，必须通过）

### 链路完整性
- [ ] 用户从入口到完成目标的完整路径是否清晰？
- [ ] 是否存在死胡同、无法返回或无法继续的节点？
- [ ] 关键操作是否有明确的下一步引导？

### 链路流畅性
- [ ] 完成核心任务需要的步骤是否最少化？
- [ ] 是否存在不必要的跳转、弹窗或确认？
- [ ] 页面间的前进/后退逻辑是否一致？

### 链路无矛盾
- [ ] 同一功能在不同入口的行为是否一致？
- [ ] 状态流转是否自洽（如：草稿→提交→审核→发布，无跳变或回退矛盾）？
- [ ] 数据在不同页面间的展示是否一致（无前后矛盾）？
- [ ] 按钮/操作的可用状态与实际业务规则是否匹配？

### 异常与边界
- [ ] 空数据状态是否有合理展示？
- [ ] 加载中/失败/超时是否有反馈？
- [ ] 权限不足时是否有明确提示和替代路径？

## P1：细节问题（P0 通过后检查）

### 界面布局
- [ ] 100% 缩放下关键内容是否一屏看完？
- [ ] 信息层级是否清晰，重点是否突出？
- [ ] 表格列数是否合理，无横向滚动必要？

### 组件与交互
- [ ] 搜索/筛选是否统一使用可输入下拉方式？
- [ ] 悬浮框/下拉框是否不留空？
- [ ] 废弃/删除操作是否有二次确认并要求填写理由？
- [ ] 视频是否支持全屏播放？
- [ ] 组件是否来自标准组件库，无自定义重复造轮子？

### 数据展示
- [ ] 时区是否统一为东8区？
- [ ] 时间筛选默认范围是否合理（T-14~T-1）？
- [ ] 数据看板内部逻辑是否自洽、可验收？
- [ ] 人名是否使用飞书中文名称，无拼音缩写？
- [ ] 是否过滤了封禁用户？

### 通知与反馈
- [ ] 长时任务（AI生成等）是否有飞书通知？
- [ ] 通知标题是否包含功能模块名称？
- [ ] 生成失败是否有机器人告警？
- [ ] 操作成功/失败是否有即时反馈？

## P2：上线与协作注意事项（最后补充）

- [ ] 新功能是否经过业务测试环境测试？
- [ ] 上线前是否发了飞书公告？
- [ ] 正式环境测试是否覆盖核心链路？
- [ ] 迭代节奏是否符合 MVP → 二期 → 三期的规划？
- [ ] 是否存在"顺便改改"的非必要结构改动？
