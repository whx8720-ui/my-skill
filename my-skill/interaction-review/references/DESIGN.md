## 页面布局与一屏优先

- 桌面端优先让标题、工具栏、核心内容和主要操作在常用视口内完整呈现
- 能不横向滚动就不横向滚动；横向滚动是数据无法合理压缩时的最后手段，不是默认布局
- 出现空间不足时，按「删除重复说明 → 压缩无效留白 → 调整列宽 → 缩短操作文案 → 将非核心字段移入详情」的顺序处理
- 不得通过缩小正文字号、压缩按钮命中区或牺牲可读性来换取一屏展示
- 表格优先使用弹性列；业务主体和高频字段获得更多空间，编号、时间、状态等固定宽度
- 非核心长文本允许省略并通过 tooltip 或详情查看，操作列不得因文案过长出现无序换行
- 只有局部数据区域可以在确有必要时横向滚动；页面主体和页面级工具栏不得跟随横向滑动

页面主体使用有最大宽度的居中容器，左右留白保持平衡。页标题、工具栏、卡片和表格使用同一内容基线；视觉居中指核心业务内容处于页面视觉中心，不是把所有文字设置为居中对齐。

## 工具栏分组与对齐

工具栏按操作目的分区，位置本身必须帮助用户预判功能：

- 左侧放筛选类：状态、人员、日期、类型、产品等会改变结果范围的控件
- 右侧放查询类：关键词搜索、搜索提交、重置和刷新
- 页面或模块主操作放标题区右侧：新增、上传、批量生成等
- 批量操作紧邻已选数量或表格顶部，不混入普通筛选项
- 危险操作与普通操作保持视觉间距，不得紧贴高频主操作
- 同组控件高度、间距和对齐方式一致；筛选组与搜索组之间使用弹性空白分隔
- 窄屏时按组整体换行，不能把同一组拆散到左右两端

## 按钮语法（四类）

| 类型 | 视觉 | 场景 |
|---|---|---|
| Primary | 实心 `#0070f3`、白字、8px 圆角、padding 8×16 | 每页唯一主行动：批量生成视频、上传并归档、开始上传、新增产品 |
| Secondary | 白底 + `--hairline-strong` 描边 + ink 字、8px | 剪映教程 / 工具、次级确认、Element 默认按钮 |
| Tertiary（`.btn-utility`） | 透明底、muted 字，hover 才出 `--surface-2` | 刷新、脚本区隔符、批量上传、批量重新处理 |
| Danger | 表格内红字链接，hover 出红色浅底 | 删除、批量删除、禁用 |

交互：`:active { transform: scale(.98) }`；focus：`2px var(--primary-focus)` outline。
按钮文案不使用装饰 emoji。所有按钮统一 `font-weight: 500`。

## 操作列形态（方案 B：图标带文字）

表格内每个动作都是 **图标 + 中文** 的 Tertiary 按钮，高 28、padding 0×8、圆角 6、字号 13、图标 15px。
同一列内不得混用图标按钮、描边按钮和纯文字链，三种形态并存正是此前的混乱来源。

写法：

```html
<div class="op-cell">
  <el-button link><ico n="download"></ico>下载</el-button>
  <el-button link type="danger"><ico n="trash"></ico>删除</el-button>
</div>
```

图标由落地页内注册的全局组件 `ico` 渲染，图标集见 `const ICONS`（1.5px 描边，viewBox 24）。
**`<ico>` 必须写成成对标签**，自闭合写法会被浏览器的 in-DOM 模板解析吞掉后续内容。

## 全局组件一致性

- 相同动作在所有页面复用同一按钮类型、图标、文案、顺序和交互反馈
- 同一动作不得在不同页面分别使用纯文字、纯图标、描边按钮等不同形态
- 下载、上传、删除、编辑、预览、刷新、详情等通用动作必须复用现有 `ico` 图标，不得新增同义图标
- 同一页面出现两次以上的相同操作时，按钮文案和图标必须完全一致
- 重复出现的操作组合应复用同一结构和 CSS 类，不使用局部样式制造视觉变体
- 新增按钮或图标前先检索现有实现；已有同义组件时直接复用
- 删除固定使用 `trash`、红色 Danger，并放在操作组最右；下载固定使用 `download`；刷新固定使用 `refresh`

## 图标可发现性（六条）

1. 只有约定俗成的图标才允许脱字：眼睛、下载箭头、垃圾桶、播放、刷新。业务动作（校准、补素材、重试）一律带中文。
2. 悬停必有中文提示，写完整动作名，不用缩写。
3. 位置固定：同一动作在所有表格里顺序一致，删除永远在最右。
4. 命中区不小于 28×28，按钮间距 2–4px，避免误点删除。
5. 危险动作标红并二次确认。
6. 一行动作超过三个时才考虑收进「更多」菜单（方案 A），否则平铺。

- 同一件事只说一次，重复的注意事项必须合并

## 验收

1. 任意页面一眼能找到唯一主按钮（蓝色圆角矩形，不是胶囊）
2. 同一张表的操作列只有一种形态，每个动作都是图标加中文
3. 任务列表里成片是行内视觉重心
4. 文字只有 ink / ink-muted / ink-subtle 三档，颜色不出现第四种灰
5. 常用桌面视口内优先完整呈现核心信息，没有可避免的页面级横向滚动
6. 筛选类控件集中在左侧，搜索、重置和刷新集中在右侧
7. 页面主体水平居中，标题、工具栏、卡片和表格基线一致
8. 相同操作在全局使用相同按钮形态、图标、文案和排列顺序
9. 空间不足时没有通过过小字号、过小命中区或无序换行换取一屏展示
10. 功能与 PRD 交互不变，只动表现层
