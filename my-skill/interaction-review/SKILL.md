# 交互评审技能

基于智创平台产品设计要求，对产品原型或网址进行结构化交互评审。核心原则：**先看整体链路是否清晰流畅无矛盾，再看细节规范，最后补充上线协作注意事项。**

## 第一步：收集必要信息（缺一不可）

在开始评审前，必须确认用户提供了以下两项，缺少任一项时主动引导补充，不要直接开始评审：

### 1. 产品原型
- 形式：原型图片、设计稿截图、Figma/Axure 链接、可访问的网址
- 如果用户只给了文字描述，要求补充可视化原型

### 2. 核心交互链路说明
- 用户需要完成什么核心任务？
- 从入口到完成的关键步骤和页面流转是什么？
- 涉及哪些角色/状态/数据变化？

**引导话术示例：**
> "为了给你做有效的交互评审，我需要两样东西：①产品原型（截图/链接均可）；②核心交互链路说明（用户要完成什么任务、经过哪些关键步骤）。这两项缺一不可，请补充一下。"

如果用户只提供了其中一项，明确指出缺少哪一项并请其补充。

## 第二步：按优先级评审

信息齐全后，严格按以下优先级顺序评审，**P0 未发现重大问题才进入 P1**，不要本末倒置。

### P0：整体交互链路（核心，占评审权重 60%）

这是评审的重中之重。检查以下维度：

1. **链路完整性**：用户从入口到完成目标的路径是否完整？有无死胡同、断点、无法返回的节点？
2. **链路流畅性**：完成核心任务的步骤是否最少？有无不必要的跳转/弹窗/确认？
3. **链路无矛盾**：同一功能在不同入口行为是否一致？状态流转是否自洽？数据在不同页面展示是否一致？按钮可用状态与业务规则是否匹配？
4. **异常与边界**：空数据、加载中、失败、权限不足等场景是否有合理处理？

**发现 P0 问题时必须明确指出：问题出在哪个环节、会导致什么后果、建议如何调整。**

### P1：细节规范问题（P0 通过后，占权重 30%）

P0 链路无重大问题后，再检查细节规范。详细标准见 `references/design-standards.md`，检查清单见 `references/review-checklist.md`。

重点检查：
- **界面布局**：一屏看完、信息层级、表格列数
- **组件交互**：搜索筛选统一可输入下拉、悬浮框不留空、废弃二次确认填理由、视频全屏、组件库规范
- **数据展示**：东8区、T-1数据、看板逻辑自洽、飞书中文名、过滤封禁用户
- **通知反馈**：长时任务飞书通知、标题含功能模块、失败告警、操作反馈

### P2：上线与协作注意事项（最后补充，占权重 10%）

评审末尾提醒：
- 新功能需经过业务测试环境测试
- 上线前发飞书公告
- 正式环境测试覆盖核心链路
- 避免"顺便改改"的非必要结构改动
- 迭代节奏符合 MVP → 二期 → 三期规划

## 第三步：输出评审报告

按以下结构输出，使用清晰的标题和列表：

```
## 交互评审报告

### 一、整体交互链路（P0）
**结论：通过 / 存在重大问题**

（如有问题，逐条列出：问题位置 → 问题描述 → 影响 → 建议）

### 二、细节规范问题（P1）
（按类别列出，标注严重程度：必须修改 / 建议优化）

### 三、上线与协作注意事项（P2）
（简要提醒）

### 四、总结
（一句话总结整体评价和最优先改进项）
```

## 评审原则

- **问题先于方案**：先指出问题，再给建议，不要一上来就提方案
- **核心优先**：P0 链路问题比 P1 细节重要得多，不要纠结像素级问题而忽略流程断裂
- **分清主次**：必须修改的问题和建议优化的问题要区分开
- **极简改动**：建议优先考虑最小改动解决问题，拒绝"顺便重构"
- **反向验证**：对每个设计决策问"不这样做会怎样"，排除伪需求
