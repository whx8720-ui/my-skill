# 方法、脱敏案例与核查

按需读取：反证与阻塞点、口径与数值核对、新证据与模型选择、报告模板与场景核查。案例只解释方法，不是新业务的默认定义。

## 反证与阻塞点

### 一次一个问题

从材料中找最影响判断的缺口，每轮只选一个问题。以下是候选集，不是一次性问卷。

| 缺口 | 可问的问题 |
|---|---|
| 目标不清 | 这次优化最希望改变用户的哪个行为或结果？ |
| 变更不清 | 这次更新具体改变了用户链路中的哪个环节？ |
| 汇报对象未知 | 这份复盘主要给谁看？ |
| 汇报人角色未知 | 你在这次优化中负责什么？ |
| 指标含糊 | 你说的三次完成率，分母是全部创建任务还是全部已完成任务？ |
| 版本边界未知 | 这次优化准确在什么时间上线？ |
| 认可行为未知 | 哪个可观察行为可以代表用户愿意采用这一步的结果？ |
| 异常原因不清 | 能否描述一条生成后废弃任务，从生成到放弃具体发生了什么？ |

分母确认后，必要时另轮追问状态、阈值和异常。时区、灰度先查材料，再问仍不明确且影响分组的事项。目标和定义已清楚时直接分析，不为凑流程重复询问。

### 两层验证

第一层检验核心判断，第二层定位最小成本可验证的阻塞条件。

| 判断 | 会改变判断的证据 | 最小必要证据示例 |
|---|---|---|
| 更多用户使用 | 任务增长来自同一批用户重复操作 | 去重用户及每人任务量 |
| 完成更容易 | 阈值比例不变但尝试均值升高，或大量任务未完成 | 同口径完成率、尝试分布、全链路状态 |
| 成本下降 | 成功任务均费低，但失败投入增加 | 同费用范围的任务成本及失败投入 |
| 创建后退出因结果差 | 没到结果产出环节，或只是误创建 | 该步事件或具体任务记录 |
| 未发布代表失败 | 已下载、审核中或等待排期 | 状态定义及对应任务证据 |
| 变化由优化导致 | 同时发生用户或任务难度变化 | 版本暴露、构成与同期变更；必要时更强比较设计 |

维护轻量假设表：假设｜预期变化｜反证条件｜所需证据｜当前结果｜下一项最小验证。只维护影响结论的假设。

一个失败案例能否定“所有任务都成功”，不能否定“平均表现改善”。相关性不足以确认技术根因；尚未证明改善不等于证明无效。

事件漏斗需要进入事件、顺序、去重和观察期；状态分布只说明观察时状态。未进入下一步可称“尚未转化”；满足终止或观察期定义后才能计流失。同一人可使用多个入口，入口去重人数之和不一定等于整体人数。

分项贡献优先看数量差。整体净增接近0或为负时，直接展示增减，不用易误导的贡献百分比。分层由业务假设驱动，不事后穷举找显著切片；极小样本不做稳定排名或归责。

数据不足解释关键异常时继续问背景或案例。用户无更多证据、要求先交付或追问不再改变判断时，列出假设与缺口后完成报告。

## 口径与数值核对

| 字典项目 | 明确内容 |
|---|---|
| 对象 | 人、任务、视频或事件；唯一标识和去重方法 |
| 范围 | 来源、版本、状态、测试记录与排除依据 |
| 公式 | 分子、分母、阈值、单位 |
| 时间 | 归组字段、时区、起止、上线边界、结果观察时点 |
| 异常 | 0次、空值、重复、负值、费用缺失的处理 |
| 来源 | 原始字段、用户补充、业务代理、可核验范围 |

三次完成率案例：确认“次数≤3的已完成任务／全部已完成任务”后，3包含在分子，7不包含，已定稿不自动计入完成。已完成但次数为0是异常；按确认规则进入主表，必要时另列去除异常的敏感性结果，不把0改成1或悄悄删除。

### 时间与成本

优先用真实版本或曝光信息。仅按创建时间切分是代理，旧任务可能在上线后执行。无其他业务规定时采用上线前 `< T`、上线后 `≥ T`，披露边界归属；已确认的不同业务规则优先。

合并有关导出，按真实唯一键处理重叠，再按时间筛选；不要以标题替代可靠标识去重，不把上线当天整天丢弃。窗口不等长可补相同时长比较或按暴露量标准化，但不能无说明替换用户要求的总量；核查数据是否覆盖所需窗口。

创建队列的导出状态和“当周完成量”不同。没有历史事件就不能重建周末快照；说明结果成熟度对完成比例的影响。

- 环比＝（后－前）／前；前值0时不可计算，报告绝对变化。
- 76.9%→95.0%约增加18.1个百分点，不是增长18.1%。计算用原始精度；分母0显示不可计算。
- 尝试任务均费＝纳入费用的尝试任务费用／这些任务数。
- 成功任务自身均费＝成功任务自身费用／费用完整的成功任务数，披露费用覆盖率。
- 全部投入分摊到成功产出的成本＝同一队列全部纳入费用／该队列成功产出数；明确是否包含失败、待处理和中间成果的投入，不误称最终生命周期成本。
- 总花费上升可能仅因使用量上升。单位成本变化可能来自任务构成。前后使用同一状态和费用范围，不混用“完成”与“完成＋已定稿”。

### 脱敏案例：上线时刻改变分组

以下历史案例固定值用于核对方法，不能作为未来报告真实输入。导出分别43、46条，第二份有6条创建于9月20日17:58之前；合并后按创建时间重分如下。窗口不等长，创建时间不是实际版本暴露。

| 指标 | 上线前 | 上线后 |
|---|---:|---:|
| 全部创建 | 49 | 40 |
| 内部创建 | 35 | 21 |
| 外部创建 | 14 | 19 |
| 外部已生视频任务 | 8 | 16 |
| 外部已完成 | 8 | 4 |
| 外部未生成且废弃 | 5 | 3 |
| 外部生成后废弃 | 1 | 7 |

这些是交叉维度，不能直接把各行相加：已完成存在0次异常，未必属于已生视频，需核对交叉明细再画漏斗。整体减少9条，外部增加5条，内部减少14条；外部增长抵消部分内部下降，不能说整体增长。

| 指标及样本 | 上线前 | 上线后 |
|---|---:|---:|
| 完成样本三次完成率，按约定含0次 | 8/8＝100% | 4/4＝100% |
| 完成样本平均生成次数 | 12/8＝1.50 | 9/4＝2.25 |
| 剔除0次异常后的完成样本均次 | 12/7≈1.71 | 9/4＝2.25 |
| 有生成任务平均费用 | 126.22/8≈15.78 | 241.20/16≈15.08 |
| 费用已知的完成任务自身均费 | 111.41/7≈15.92 | 75.63/4≈18.91 |

阈值完成率不变与平均尝试增多可同时成立。费用表使用了不同样本，不能直接得出全链路成本改善；前期完成费用覆盖7/8需披露。若新表出现3条与2条差异，先核对测试剔除、时间边界、状态和异常，再判断是算错还是口径不同。

## 新证据与模型选择

| 新信息 | 更新动作 |
|---|---|
| 指标或状态含义修正 | 更新字典，重算相关指标和结论 |
| 上线时间、样本或版本变化 | 重分组，核对窗口，重算相关比较 |
| 可追溯业务证据 | 标明来源与覆盖范围，更新解释 |
| 新的原因猜测 | 加入假设，追问最小证据，不当事实 |

“部分任务等审核”不能证明全部未发布都因审核，也不能证明囤稿；问清覆盖多少任务及具体记录。用户口述与日志冲突时指出冲突并核实字段，不悄悄择取有利的一方。

先用口径修正、分层或敏感性分析处理，再考虑模型。重复用户、相关任务、多次切片和结构变化会影响推断。所需比较组和假设不成立时不套用显著性检验或双重差分，保留描述性结论。

小样本100%不是未来成功的确定保证；不显著不等于无效果。需要概率结论时说明抽样、依赖假设及不确定性。

贝叶斯方法仅在概率更新帮助决策时采用，说明：估计问题与决策用途；先验来源及敏感性；似然与独立性、样本选择假设；后验区间或概率。弱信息先验也说明选择依据，不把同一数据重复用于先验和更新。复杂模型检查能否再现观察数据的重要特征。

没有合理依据时定性更新，不编造概率。可选方法参考：[Stan 后验预测检查](https://mc-stan.org/docs/stan-users-guide/posterior-predictive-checks.html)。不引入 Stan 依赖；模型不能代替业务定义或因果设计。

## 报告模板与场景核查

### 四步报告骨架

**一、目标**

说明背景、上线前要解决的问题、优化事项与预期机制、上线信息和汇报背景。附统计口径表，记录样本、窗口、版本依据、公式、状态、成本范围和数据限制。目标表可用“业务目标｜指标与基线｜预期方向或既定目标值｜提出时间与来源”。没有事前目标值就标注未设定，不用事后表现重写目标。

**二、结果**

每项采用“结论句→相邻依据表→问题与证据边界”。表含指标、前后数值、变化和样本范围，优先分析整体及贡献、链路转化与退出、最终效果与成本。适合时附图，不把状态快照当已验证事件序列。

例如“外部创建增加5条，但整体减少9条，外部增长抵消部分内部下降”，紧接分项表。另用“评估问题｜当前结论｜主要依据｜待确认事项”表对应目标，区分已观察到改善、未见改善与数据不足以判断。不能从使用量上升推导效率或成本改善。

**三、原因**

| 关键结果或问题 | 所在环节与影响范围 | 可能原因 | 支持证据及来源 | 替代解释或反证 | 当前判断与缺口 |
|---|---|---|---|---|---|
| 根据实际结果填写 | 数量、分群或任务范围 | 只列相关假设 | 数据表、记录或用户补充 | 足以改变判断的证据 | 已支持的部分及最小验证 |

逐层下钻，继续追问关键背景和具体案例。证据支持“某任务反馈动作不相似”不等于支持“抽帧算法导致动作失败”；要区分症状与技术原因。改善也需核对构成、版本和观察窗口等替代解释。无法确认时保留假设。

**四、对策**

| 对应问题或有效做法 | 原因证据状态 | 建议行动与优先级依据 | 预期指标变化 | 验证方式与判断标准 | 适用条件或待确认项 |
|---|---|---|---|---|---|
| 引用前文结果 | 已支持／待验证 | 针对性改进、最小验证或有条件复用 | 对应目标指标，兼顾相关成本 | 样本、比较方式、观察窗口、保留或调整条件 | 未定参数明确标注 |

原因不清时，收集能区分关键假设的最小证据本身就是对策，不先承诺大规模改造。没有资源信息时，优先级依据影响范围、证据强度与验证成本定性说明。数值门槛、负责人和日期未确认时列为建议或待定，不当作用户承诺。

为复用提炼“适用情境—做法—验证指标—保留或调整条件”。已支持的经验和未验证假设分开，不能把一次小样本变化称为普遍规律。下一轮把已确认的对策目标与口径作为起点，重新检查适用性。

四步需可追溯：目标对应结果，原因对应结果差异，对策对应原因或证据缺口。量化核心结论有相邻数据表；原因中的非量化解释标明补充证据来源。报告建议不授权自动执行变更或对外发布；用户缩小输出范围时遵守当次要求。

### 场景核查

| 场景 | 应有行为 |
|---|---|
| 只给文件，目标不清 | 检查字段；一次问一个业务问题，不先下效果结论 |
| 已说明目标、时间和公式 | 复用答案，只问剩余关键缺口 |
| 只写“三次完成率” | 问清分母，再确认状态与边界 |
| 上线改为9月20日17:58 | 案例重分49→40、外部14→19，披露窗口和版本限制 |
| 100%但均次及完成成本升高 | 同时呈现，不把阈值不变写成效率改善 |
| 新解释为审核或囤稿 | 追问范围或案例，不当根因已经证实 |
| 成本范围切到完成加中间状态 | 前后同步重算，说明回答了不同问题 |
| 无更多证据或要求交付 | 输出已知结果和关键缺口，停止无价值追问 |
| 换成注册、支付业务 | 重建实际链路和成功状态 |
| 无事前目标值 | 说明基线与预期方向，不从结果倒推达标线 |
| 原因尚未证实但需要对策 | 提出能区分假设的最小验证，不直接承诺改造 |
| 某项结果有改善 | 说明证据和适用条件，有条件沉淀可复用做法 |
| 最终报告 | 四步相互对应；每个核心结论可追溯，事实、推断和建议分开 |
