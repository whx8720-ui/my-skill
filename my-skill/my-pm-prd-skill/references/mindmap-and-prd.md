# 页面导图与产品说明书对应

页面字段导图是信息结构正本，ASCII 线框说明布局。名称、属性、默认、校验与文案在各产物间一致。正文按链路顺序组织页面。

## 导图粒度

```markdown
# 产品名称
## 阶段或模块
### 页面名称
- 对应链路步骤：
- 页面目标：
- 角色 / 权限：
- 入口：
- 出口：
#### 区域名称（按页面从上到下）
- 组件：名称与复用依据
- 字段：名称
  - 含义 / 类型：
  - 必填 / 默认：
  - 校验 / 可编辑条件：
  - 来源 / 空态 / 错误文案：
- 操作：按钮名称
  - 触发 / 可用条件：
  - 正常反馈 / 去向：
  - 对应后台规则：
  - 分支 / 失败 / 恢复：
```

未知属性逐项确认，不用填满所有属性来代替判断。不适用的属性省略或说明原因。

| 导图内容 | 说明书位置 |
| --- | --- |
| 产品名称 | 文档标题 |
| 页面目标、角色、入口、出口与步骤 | 核心正常链路及页面定位 |
| 区域、字段、组件、按钮 | 页面前端交互与线框 |
| 对应后台规则 | 紧接对应前端要求的后台处理逻辑 |
| 分支、失败、恢复 | 对应页面细节，不写入核心链路 |

复杂弹窗和抽屉作为关联页面展开，注明目标、触发入口、字段、按钮和返回页面。字段在多个页面出现时复用已确认定义，冲突先确认再同步修订。

## 用户提供导图转说明书

先读导图与其他材料。已有用户故事与权限路径足够明确时整理确认；否则先问清 Who / What / Why，再确认分权限正常链路。

保留页面、字段、按钮的名称和顺序。只补开发和验收必要的缺口，不新增无依据功能。若用户只要求导图整理或局部页面说明，按其范围交付，不强迫生成全套 PRD。

确认页面信息结构后再确认线框。已有可用且确认的原型或布局依据可直接引用，不重复要求重画。终稿采用页面为主体的模板；用户故事集中在文档最前面一次。

## 对齐检查

- 页面字段与校验、默认、空态和文案保持一致。
- 正常跳转对应核心链路；条件分支与错误对应页面细节。
- 前端操作有相邻的后台处理说明和验收结果。
- 每个线框控件能对应到已确认导图或原型依据。
