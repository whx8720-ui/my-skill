# System Prompt Optimizer

## Overview

本技能在 prompt-optimizer 的基础上，专门处理「可复用系统提示词」。

两类提示词的失效方式完全不同。一次性任务提示词只需在当次输入上表现好；可复用系统提示词必须在未来所有输入上都成立，因此它的主要故障不是表达不清，而是规则之间互相矛盾、某次测试用例被写成硬规则、模型向常见默认值漂移。

本技能的核心动作是：把随输入变化的量写成公式，把裁决规则收敛成唯一一张表，把具体用例从提示词正文中剥离到回归用例。

## 与 prompt-optimizer 的分工

一次性任务提示词（输入已知且固定、写完即用）使用 prompt-optimizer。
可复用系统提示词（下述判定信号命中任意一条）使用本技能。
无法判定时直接问用户，不要默认按一次性处理。

## Workflow

### Step 0: 判定交付物类型

先判定，再进入后续步骤。判定信号命中任意一条即按可复用系统提示词处理：

- 提示词中含 `{{变量}}`、占位符或待填字段
- 会被不同输入反复调用，而不是只跑一次
- 面向多个使用者，或将被固化进产品、工作流、Agent
- 带固定输出模板、固定字段、固定章节结构
- 用户称其为 system prompt、系统提示词、母版、模板、规则集

判定结果决定后续每一步是否启用可复用分支。

### Step 1: 分析原提示词

先执行 prompt-optimizer 的通用分析（清晰度、具体性、结构、格式、复杂度）。

再执行可复用专项故障扫描，逐项检查 `references/reusable-system-prompts.md` 中的六种故障模式：

1. 案例焊死：某次测试的具体值被写成必须遵守
2. 规则打架：同一维度存在多份优先级或多套裁决顺序
3. 默认值吸附：模型会跳到常见整数、常见档位、常见长度
4. 字段串味：输出模板中两个字段职责重叠，同一事实被抄两遍
5. 优先级倒挂：真正的硬约束排在软性目标之后
6. 示例污染：示例中的角色、道具、数值出现在实际输出中

扫描结果直接构成 Analysis 段的问题清单。

### Step 2: 识别核心意图与调用边界

除 prompt-optimizer 的四个问题外，补充确认：

- 这份提示词会被哪些输入调用，输入的取值范围是什么
- 哪些量随输入变化，哪些量恒定
- 哪些约束是硬的（违反即废），哪些是偏好（可让位）
- 失败长什么样：用户是怎么发现它出问题的

最后一问最关键。用户报的故障现象通常直接指向被焊死或被倒挂的那条规则。

### Step 3: 应用优化原则

先应用 prompt-optimizer 的六条通用原则（清晰直接、提供背景、具体化、结构化、善用示例、允许不确定）。

再应用可复用专属五条：

**变量化**
所有随输入变化的量必须写成公式或占位符，禁止写成具体数值。用户给的某次数值只能作为回归用例，不进提示词正文。

**单点定义**
同一约束只定义一次。同一条规则在多节重复出现时，保留一处，其余改为引用。重复定义是规则打架的温床。

**冲突裁决唯一化**
只保留一张裁决表。禁止并存多份优先级列表，禁止同一维度出现两套排序。模型遇到两套排序时会挑对自己最省事的一条。

**边界枚举**
对每个变量列出超上限、低于下限、缺失、为空四种取值的处理方式。缺哪种，模型就在哪种上自由发挥。

**默认值防吸附**
模型会向常见默认值靠拢。凡存在此风险的量，明确写出「除非按公式算出的值恰好等于该值，否则禁止使用」，并列出需要防范的具体默认值。

### Step 4: 高级技术的可复用改写

Chain of Thought、Prefilling、Structured Output 的用法与 prompt-optimizer 一致。

示例（few-shot）的用法必须改写：

- 可复用提示词中的示例只用于示范方法，不得示范内容
- 必须在示例前加边界声明：示例只解释规则如何执行，禁止把示例中的具体角色、数值、场景、措辞写入实际输出
- 优先使用抽象模式示例（输入形态 → 处理方式），而非具体实例
- 确需具体示例时，使用与目标领域明显无关的素材，降低污染概率

Prompt Chaining 在可复用场景下慎用：链路越长，跨轮次状态越难约束。优先在单份提示词内用结构化分节解决。

### Step 5: 交付优化结果

先交付 prompt-optimizer 的三段格式：Analysis、Optimized Prompt、Improvement Explanation。

可复用系统提示词额外交付三项：

**变量清单**
每个变量的含义、取值范围、边界处理。

**冲突裁决表**
规则相互矛盾时的唯一裁决顺序。

**回归用例**
3 到 5 组输入与期望输出特征，作为独立交付物给用户，不写进提示词正文。用户提供的故障用例应放在这里，而不是写成规则。

### Step 6: 迭代（条件触发）

仅在用户提出修改意见时执行。

遵从用户已有的输出格式规则。用户规则要求纯文本、禁止追问或禁止寒暄时，按用户规则执行，不追加确认性提问。

## Quality Standards

一次性任务提示词沿用 prompt-optimizer 的七项标准。

可复用系统提示词额外核对：

- [ ] 没有把某次输入的具体值写成硬规则
- [ ] 同一约束没有在多处重复定义
- [ ] 只有一张冲突裁决表
- [ ] 每个变量的边界取值都有明确处理
- [ ] 输出模板中的字段职责互不重叠
- [ ] 含示例时有边界声明
- [ ] 存在默认值吸附风险的量已明确禁用常见默认值
- [ ] 回归用例独立交付，未混入提示词正文
